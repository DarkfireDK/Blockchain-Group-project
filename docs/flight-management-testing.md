## 浏览器验收步骤

1. 启动项目，进入“运营管理”，输入已有保单 ID 并查询。核对航班号、计划起飞时间、保额、受益人与保单一致；查询不存在的 ID 应提示未找到。
2. 切换普通旅客钱包，延误报告按钮应不可用，并说明上报权限；普通钱包仍可查询。
3. 使用两张独立测试保单测试理赔和退款，同一张保单不可重复结算。Debug 调整会影响全部保单。
4. 理赔路径：连接授权上报员（本地通常为部署者），在计划起飞之后、报告窗口内，选择延误场景。输入低于门槛的分钟数应禁用；输入本保单门槛及以上，核对 ID/受益人后提交并在钱包确认。应显示交易编号，受益人收到全额赔款，保单进入“已结束”，再次查询不能重复报告。
5. 正常路径：选择“正常/未达门槛”，应只显示等待退款说明，不弹出交易、不提前退款。保障结束但仍在24小时宽限期内不可退款；Debug 推进到报告截止时间之后，界面自动更新为待退款，点击结算并确认后，持有人收到可退保费。
6. 市场与状态：Debug 推进跨过计划起飞时间后，等待约2秒或点击刷新状态，保单应不可挂牌/购买；跨过保障结束和宽限期边界后分别显示保障结束、待退款。
7. 断开本地链，时间查询失败时应提示连接问题、暂停管理面板交易；恢复后可刷新。
8. 拒绝钱包确认不应产生成功提示或写入结果。同一航班多张保单需逐张查询及上报，当前没有批量结算。
