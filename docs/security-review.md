# 安全扫描与规则核对（2026-11-10）

运行 Slither 0.11.5，启用101个检测器；原始结果全部保留在 evidence/slither.json 和 slither.log。通过适配器读取Hardhat 3实际编译输入、AST及字节码，没有用替代合约扫描。依赖库及专用攻击测试合约从告警输出中过滤，6份业务合约均已覆盖。

本次发现11项：High 2、Medium 4、Low 4、Informational 1。**不是零告警，也不是独立审计。** 六项高/中告警逐条分析如下：

| 告警 | 判断与依据 | 验证 |
|---|---|---|
| fundPolicy arbitrary-send-erc20 | 该入口只授予Insurance的INSURER_ROLE；Insurance仅以msg.sender作为payer，资金只能进入池，金额受固定报价限制。属于受控代扣；管理员不得把该角色授予不可信地址。 | 未授权资金操作、保费授权不足回滚、购保资金测试 |
| PolicyMarket.buy arbitrary-send-erc20 | 检测器把同名ERC721 transferFrom标记成ERC20；卖方自行挂牌，成交时校验当前所有者，且NFT需单独批准给市场。USDC仅从买方msg.sender扣取，支持maxPrice。 | 转售余额与NFT归属、过期/改价/转移后挂牌拒绝 |
| deposit balance-delta strict equality | 有意要求收到恰好amount；不支持收费/rebase代币，防止按未到账金额铸造份额。严格相等是本测试币范围的约束。 | 正常存款、资金守恒；部署仅使用新建MockUSDC |
| fundPolicy balance-delta strict equality | 同上，足额保费才允许建立准备金；失败整笔回滚。 | 授权不足回滚和准备金测试 |
| deposit shares == 0 | 有意拒绝向下取整成零份额，避免捐赠攻击吞掉存款。 | 零份额捐赠攻击测试 |
| withdraw amount == 0 | 有意拒绝烧掉份额却得到零金额的赎回。 | 赎回计算、准备金限制和份额公平性测试 |

4项Low是保险及市场的时间戳比较：时间窗口是业务需求，测试包含边界，采用24小时报告宽限期；不把区块时间视为真实航班证据。1项Informational是Insurance未显式继承Oracle定义的接口；函数选择器兼容且调用已通过测试，不影响运行。

`scripts/slither-reviewed.json`保存本次六项已审阅告警的ID及完整合约源码摘要。扫描仍输出全部告警。源码变化会使审阅记录失效；新增或未审阅的High/Medium导致非零退出，需重新核对，不能自动接受。

## 已落实的控制
- 固定教学报价：保额10–5000测试USDC，保费向上取整为保额2%，其中50%可退。不是精算定价，不能据此承诺商业盈利。
- Oracle地址与延误阈值按保单快照；后台更改仅影响新保单。Oracle仍是授权人工报告者，未接入真实航班API。
- 报告允许起飞时刻起至保障结束后24小时（含边界），退款必须严格晚于此窗口；杜绝窗口重叠，交易仍需主动发起。
- LP份额净值与可提款流动性分别计算。未结算保费不计入LP净值；理赔损失由LP承担，结算后才确认风险收益。准备金同时保留保额与可退款项，采用保守约束。
- 使用SafeERC20、先更新状态再转账、重入锁；NFT接收回调重入攻击已被实测阻断。
- 市场仅在起飞前交易，校验NFT归属并要求买方最高可接受价格；前端单独授权该NFT。
- 暂停仅禁止新保单，理赔与退款仍开放。合约不可升级，不提供管理员抽走资金的入口。发现问题后暂停新业务并另行部署，经用户选择迁移，不能修改既有合约。

## 保留的信任与限制
人工Oracle可提交错误信息；保费固定且未建模相关性/逆向选择；多身份可购买同航班保单。完全准备金约束限制资金敞口，但不替代可靠承保和可信航班数据。LP提款受活动保单约束。测试币允许任意mint，仅用于课堂测试；所有部署只使用MockUSDC。未进行第三方审计或穷尽模糊测试。
